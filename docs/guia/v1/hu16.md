# HU-16 · Identificación por documento de identidad

Ficha con la narrativa, los mockups y los criterios: `fichas/sprint3/hu16.pdf`.

## De dónde parte

Se implementa junto con HU-15: es el mismo campo y la misma consulta.

## Decisiones

- **Un solo campo para los dos identificadores.** El personal teclea lo que el estudiante
  le muestra. Pedirle que elija antes el tipo de dato sería una decisión de más con la
  fila esperando.
- **La búsqueda cruza los dos campos**: `codigo_universitario = X OR documento_identidad
  = X`. Por eso puede devolver más de un estudiante, aunque cada campo sea único por
  separado: el código de uno puede ser el documento de otro.
- **Con varias coincidencias el sistema no adivina.** Devuelve la lista con el código y
  el documento de cada uno, y la pantalla ofrece elegir. Quedarse con el primero sería
  registrar el ingreso de otra persona.

## Backend

`HabilitacionGateway::buscarCandidatos` devuelve todas las coincidencias; el controlador
responde `data` con una o `coincidencias` con varias.

## Frontend

En `paginas/ingreso/PuntoControl.jsx`, la lista de coincidencias con un botón «Es este»
por fila.
