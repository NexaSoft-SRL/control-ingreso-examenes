# HU-01 · Autenticación de usuarios

Ficha con la narrativa, los mockups y los criterios: `fichas/sprint1/hu01.pdf`.

## Decisiones

- **La sesión es de servidor**, con la cookie de Laravel, no un token en el navegador.
  El frontend solo recuerda a quién saludó, para decidir a qué pantalla mandar; toda
  ruta `/api` exige sesión en el backend.
- **Mensaje de error único** ante credenciales incorrectas, y **respuesta única** al
  pedir un restablecimiento: si cambiaran según el caso, el formulario revelaría qué
  correos están registrados.
- **`password_changed_at` nulo significa "todavía usa la contraseña que le dieron"**.
  Es un dato, no una bandera aparte, y sirve además para saber cuándo la cambió.
- **El bloqueo del sistema mientras no cambie la contraseña vive en un middleware**, no
  en cada controlador: así ninguna historia futura se olvida de aplicarlo.
- **El token del enlace se guarda cifrado** y se borra apenas se usa. Quien lea la tabla
  `password_reset_tokens` no puede fabricar un enlace válido.
- **La contraseña inicial viaja solo al correo**: no se devuelve en la respuesta ni se
  escribe en la bitácora.
- **Queda fuera**: el alta de usuarios tiene endpoint pero todavía no pantalla; la hace
  HU-02 junto con roles y permisos.

### API

| Método | Ruta | Sesión | Cuerpo | Respuestas |
|---|---|---|---|---|
| POST | `/api/auth/login` | No | `email`, `password` | 200 con el usuario y `debe_cambiar_contrasena`; 401 credenciales; 422 validación |
| POST | `/api/auth/logout` | Sí | — | 204 |
| POST | `/api/auth/contrasena` | Sí | `contrasena_actual`, `contrasena_nueva`, `contrasena_nueva_confirmation` | 200; 422 si la actual no coincide o la nueva no cumple |
| POST | `/api/auth/contrasena/olvide` | No | `correo` | 200 siempre, exista o no la cuenta |
| POST | `/api/auth/contrasena/restablecer` | No | `correo`, `token`, `contrasena_nueva`, `contrasena_nueva_confirmation` | 200; 422 si el enlace venció, ya se usó o es falso |
| POST | `/api/auth/usuarios` | Sí | `nombre`, `correo` | 201; 422 si el correo ya existe |

Mientras el usuario conserve la contraseña inicial, cualquier otra ruta `/api` responde
**409** con `debe_cambiar_contrasena: true`.

### Operaciones que deja en la bitácora

`sesion.iniciar`, `sesion.cerrar`, `sesion.intento_fallido`,
`usuario.cambiar_contrasena`, `usuario.solicitar_restablecimiento`,
`usuario.restablecer_contrasena`, `usuario.crear`.

## Frontend

| Ruta | Pantalla | Acceso |
|---|---|---|
| `/login` | `paginas/auth/Login.jsx` | Público |
| `/olvide-contrasena` | `paginas/auth/OlvideContrasena.jsx` | Público |
| `/restablecer-contrasena?token=…&correo=…` | `paginas/auth/RestablecerContrasena.jsx` | Público, con el enlace del correo |
| `/cambiar-contrasena` | `paginas/auth/CambiarContrasena.jsx` | Con sesión |

`TarjetaAuth.jsx` y `CampoContrasena.jsx` son el marco y el campo que comparten las
cuatro. `componentes/sesion.js` guarda al usuario de la pestaña y
`componentes/Aplicacion.jsx` protege las rutas y atiende los 401, 419 y 409 de la API.

## Cambios en el contrato de arquitectura

Dos ampliaciones deliberadas, ninguna con `@phpstan-ignore` ni excepciones al
verificador:

1. La capa `Http` puede usar la respuesta base de Symfony, que es el tipo que devuelve
   todo middleware.
2. Se suma `Infrastructure/Mail`: enviar correo es infraestructura, como la persistencia.
